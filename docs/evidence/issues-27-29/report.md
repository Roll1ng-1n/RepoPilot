## #27 的证据边界

`tests/repopilot/test_context_progress.py` 使用旧评测中两个 full/history-inventory checkpoint 的历史前缀，检查请求预算、初始失败验证、六份合同、目录约束、工具配对、原历史不变以及恢复后重建一致。回放使用最终 checkpoint 的 profile/plan，属于离线机制验证，不是原始逐次请求快照。

原 inventory 夹具通过真实本地工具执行：初始验证失败、批量读取合同与源码、应用补丁、验证、完成任务。共 5 次脚本模型交互、2 次 `verify_task`，最终 `SUCCEEDED` 且隐藏 verifier 通过。脚本模型使用旧 baseline 的已知补丁，验证的是裁剪后的信息可见性和执行路径，不能证明真实模型会选择同样的行动。

历史记录携带调用 ID 与历史索引；摘要摘录明确标记为历史观察，可能因后续修改过时，不会替代当前验证或授予任务完成权限。记录不成为新的 checkpoint 权威状态，Resume 从完整消息重建。默认上下文策略仍为 `none`。
